# Проверка геометрии исходных заготовок GarmentCode

Дата: 2026-09-13. Запущен исходный GarmentCode на зафиксированном commit `d449629979028123a5c4dc9e732a2ec19b7fce31`, без изменений исходных файлов. Это отдельный исследовательский эксперимент, а не реализация движка Kroika и не полный контрольный чертёж платья.

## Условия

Взяты три синтетических профиля S/M/L из [control-examples.json](../references/stage2/control-examples.json), с однократным переводом mm → cm на входе upstream. Прибавки нулевые только для изоляции правил источника. Дополнительные синтетические значения: рост 1600/1700/1800 mm, длина головы 230 mm для размещения панелей, расстояние ягодичных точек 180/200/220 mm. Они записаны явно и не подставляются в реальные мерки клиента.

Построены `BodiceFrontHalf`, `BodiceBackHalf` и две `FittedSkirtPanel`. Параметры юбки: длина 550 mm от исходного уровня талии, коэффициент расширения 1.1, угол низа 0, без разрезов, заднее удлинение 1.05 по правилу автора. Горловина и пройма ещё не вырезаны. Измеряются реальные длины рёбер интерфейсов, исключая стороны вытачек, но без применения коэффициентов сборки/посадки. Эти числа не описывают окончательно оформленный шов после всех преобразований.

Встроенная проверка upstream не обнаружила самопересечений ни у одной из 12 заготовок; оптимизаторы не выдали сообщений в захваченный журнал. Это ограниченная проверка исходного ядра, не независимое доказательство геометрической корректности.

**Вывод:** исходные размеры действительно превращаются в криволинейные панели, но равенство проекционных ширин не гарантирует равенства реальных швов. Задняя талия лифа немного длиннее целевой прямой талии юбки. Сырые боковые соединения требуют дальнейшего оформления и явного учёта посадки; их нельзя автоматически принимать как равные с допуском 1 mm.

Это не утверждение об ошибке готового изделия upstream: мы намеренно измерили промежуточные блоки. В `FittedSkirtPanel` коэффициент 1.05 одновременно удлиняет заднюю область бедра и задаётся как `ruffle` соответствующей части бокового интерфейса. Для реального шитья величину и допустимость такой посадки нужно проверить на ткани. Бок лифа в этом эксперименте ещё включает область будущего выреза проймы.

Результат сохраняет `seams_reconciled=false` и `expert_reviewed=false`. Полные данные, версии зависимостей, hash исходных контрольных профилей и дополнительные входы: [upstream-block-observations.json](../references/stage2/upstream-block-observations.json). Этот файл — журнал фактического запуска, а не независимый математический эталон.

## Воспроизведение

Основная проверка `python3 scripts/verify_stage2.py` по-прежнему работает без зависимостей. Для этого дополнительного эксперимента требуется отдельное Python 3.12-окружение и исходник GarmentCode. Проверяющий скрипт откажется работать с другим commit или изменёнными отслеживаемыми файлами upstream.

Из корня Kroika в Linux/macOS, выбрав свободные пути для checkout и окружения:

```bash
git clone https://github.com/maria-korosteleva/GarmentCode.git ../GarmentCode-reference
git -C ../GarmentCode-reference checkout d449629979028123a5c4dc9e732a2ec19b7fce31
python3 -m venv ../kroika-reference-env
../kroika-reference-env/bin/python -m pip install -r references/stage2/audit-requirements.txt
../kroika-reference-env/bin/python scripts/audit_upstream_blocks.py ../GarmentCode-reference > /tmp/kroika-observed.json
```

CairoSVG требует системную библиотеку Cairo; использованное Linux-окружение её уже содержало. В файле зависимостей зафиксированы прямые пакеты проведённого эксперимента, а не полный lock транзитивных зависимостей. На другой платформе сравнивать длины с вычислительным допуском, не требовать побитового совпадения JSON. Сохранённый журнал не перезаписывается командой воспроизведения.

До проверки посадки на макетах ни успешный запуск этого скрипта, ни отсутствие самопересечений не разрешают производственный экспорт.
