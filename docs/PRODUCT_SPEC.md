# PRODUCT_SPEC — требования к первой версии

Версия: **0.13.0, рабочая база** · Дата: **2026-09-21** · Текущий этап: **13/15**.

Рабочая база требований перенесена в контракты этапа 3, каркас этапа 4, мастер мерок этапа 5 и геометрическое ядро этапа 6. Пользователь подтвердил ручное снятие мерок и поручил разработчику выбрать рабочие ответы. Методика, инструкции формы и посадка специалистом ещё не проверены. Архитектура: [ARCHITECTURE.md](ARCHITECTURE.md).

## 1. Пользователь, задача и результат

Основной пользователь — тётя заказчика, практикующий закройщик. Она работает с женской одеждой и индивидуальными мерками, выбирает конструкцию и проверяет посадку.

Продукт — русскоязычное веб-приложение для ноутбука с адаптивным интерфейсом. Оно помогает превратить подтверждённое описание фасона и мерки в комплект векторных деталей, проверить их и распечатать A4 1:1. Отдельные мобильное и настольное приложения в первую версию не входят.

Первый полезный результат: закройщик вводит свой профиль мерок, задаёт поддержанный фасон, видит линии шва и среза, получает отчёт проверки и печатает комплект с контрольным квадратом. Посадку подтверждает изготовление макета.

Источник требований — приложенный мастер-промпт v2. Все «решения из задания» ниже извлечены из него или текущего запроса пользователя; это не запись проведённого интервью.

## 2. Границы MVP

| Область | Решение из задания для первого вертикального MVP |
| --- | --- |
| Изделия | Восемь ограниченных симметричных вариантов: платье, сарафан, юбка, топ, блузка, рубашка, жилет и лёгкий жакет |
| Ткань | Неэластичная ткань; конкретные свойства и допустимые диапазоны согласовать |
| Лиф | Прилегающий или полуприлегающий; нагрудные и талиевые вытачки |
| Вырез | Круглый, V-образный, квадратный в пределах подтверждённых правил |
| Рукав | Без рукава, короткий или длинный базовый втачной рукав |
| Юбка | Прямая или А-силуэтная |
| Застёжка | Центральная молния на спинке |
| Сарафан | Без рукавов; редактируемые длина, ширина и положение бретелей, глубина переднего и заднего выреза |
| Отделка срезов | Линия шва и отдельная линия среза; режимы с припусками и без них; технология обработки требует ответа тёти |
| Ввод фасона | 1–4 изображения и подтверждение признаков; ручной ввод доступен при отсутствии изображения или API |
| Результаты | Интерактивный SVG, цельный SVG 1:1, A4 PDF 1:1, JSON проекта |

Это целевой объём этапов 5–11, а не список уже работающих функций. Каркас проекта, SQLite и mock уже доступны; каждый конструктивный вариант становится доступен только после проверки его правил и сочетаний.

**Выбранный первый контрольный сценарий:** полуприлегающее платье с круглым вырезом, без рукавов, с вытачками, А-силуэтной юбкой и молнией по центру спинки. Длина и расширение низа задаются явно. В комплект должны входить обтачки горловины/пройм. Это решение разработчика по поручению пользователя; полный блок и посадка ещё не проверены.

Внутри MVP сначала проверяется этот один фасон, затем остальные варианты платья и сарафана. Рельефы отложены: исходное задание допускает для MVP вытачки **либо** заранее реализованный рельеф; здесь выбран более узкий вариант с вытачками.

## 3. Отложено

- Этап 12 реализован автоматикой: отдельные юбка, топ, блузка, рубашка и жилет; физическая приёмка каждого ещё открыта.
- Этап 13 реализован автоматикой для одного лёгкого однобортного жакета; бумажная, экспертная проверка и три макета на разных фигурах ещё открыты.
- Этап 14: брюки, шорты и комбинезоны.
- Отдельное позднее расширение: лёгкие пальто, трикотаж, корсеты, сложная асимметрия, драпировки, сборки, складки, сложные рукава и воротники.
- Вне первого MVP: карманы, подкладка и декоративные усложнения платья, 3D-примерка, раскладка на ткани, расход ткани, градация размеров, свободное перемещение точек, DXF и CAD-интеграции, плоттерный PDF.

Выбрана обработка горловины/пройм обтачками. Они входят в полный комплект и должны быть отдельно формализованы; пока не построены.

## 5. Мерки и параметры для обсуждения

Это перечень кандидатов из задания, а не окончательный обязательный набор. Точки измерения, полные/половинные величины, диапазоны, контрольные зависимости и точность определяются выбранной методикой на этапе 2.

| Группа | Кандидаты |
| --- | --- |
| Тело: основные | Рост; обхваты груди, талии, бёдер, шеи; ширина груди и спины |
| Тело: баланс лифа | Длины спины и переда до талии; высота груди; расстояние между центрами груди; длина плеча; наклон/контрольная высота плеча; глубина проймы; контрольные косые высоты плеча при необходимости |
| Тело: нижняя часть | Высота бёдер/расстояние до линии бёдер — уточнить, один ли это показатель в выбранной методике |
| Тело: при наличии рукава | Обхваты верхней части руки, запястья, при необходимости локтя; длина до локтя и длина руки по правилам методики |
| Модель, не мерки тела | Желаемая длина изделия и длина от талии; длина рукава изделия; глубины вырезов; параметры бретелей |
| Ручные особенности | Добровольно заданные особенности осанки; асимметричная коррекция за пределами первого симметричного MVP |

Для каждого поля нужны: идентификатор, русское название, единица, условие обязательности, диапазон, инструкция, источник `user/preset/derived`. Для `derived` показывать формулу. Длина руки — мерка тела; длина рукава изделия — отдельный параметр фасона. Рабочие определения и системы отсчёта приведены в [PATTERN_METHOD.md](PATTERN_METHOD.md); удобство ручного снятия ещё требует практической проверки.

## 6. Технические и организационные ограничения

- Направление — веб-приложение. Из задания для пустого репозитория предложены React/TypeScript/Vite, Python 3.12/FastAPI/Pydantic, отдельный чистый Python-движок, SQLite, локальное файловое хранилище, Docker Compose и запуск без Docker. Это ориентир для этапов 3–4; репозиторий изучен и исходно содержит только README.
- Ключи и передача изображений — только через backend. Численные параметры тела не выводятся из фото и не передаются провайдерам для анализа фасона.
- Имена AI-моделей в исходном файле — примеры. Их существование, возможности, цены и доступность здесь не подтверждаются; актуальные конфигурации проверяются по официальной документации перед интеграцией на этапе 10.
- Локальный MVP работает без регистрации. Сетевой доступ и способы ограничения доступа нужно определить до размещения; публикация сайта не входит в этап 1.
- Пробные прибавки и инженерные допуски назначены в [FIT_AND_TOLERANCES.md](FIT_AND_TOLERANCES.md); это не экспертно проверенные нормы. Скалярные FormulaRecord оформлены на этапе 2. JSON Schema/OpenAPI и контракт канонической геометрии оформлены на этапе 3; математическое ядро реализовано и проверено на этапе 6, но формул деталей в нём ещё нет.
