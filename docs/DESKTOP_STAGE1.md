# Кройка в отдельном окне — этап 1

Этот документ описывает первый этап. Текущий запуск, пользовательская папка данных, настройки
Gemini и импорт описаны в [DESKTOP_STAGE2.md](DESKTOP_STAGE2.md); они заменяют указанные ниже
исходные пути хранения данных и профиля окна.

Добавлен запуск приложения для ПК на базе pywebview. Окно использует готовую сборку того же
React-интерфейса, а управляемый дочерний процесс запускает существующий FastAPI и движок лекал.
Vite и браузер во время работы окна не запускаются. Веб-версия сохраняет прежний способ запуска.

## Запуск из исходников на Windows

На первом этапе ещё нужны Python 3.12+ и Node.js 24+: launcher устанавливает зависимости и
собирает интерфейс. Установщик с включёнными зависимостями относится к этапу 3.
Для окна требуется Microsoft Edge WebView2 Runtime:
<https://developer.microsoft.com/microsoft-edge/webview2/>.

Откройте PowerShell в корне распакованного актуального репозитория:

```powershell
py -3.12 scripts/start_desktop.py
```

Для анализа фотографий через Gemini задайте окружение в том же PowerShell перед запуском:

```powershell
$key = Read-Host "Gemini API key" -AsSecureString
$env:GEMINI_API_KEY = [System.Net.NetworkCredential]::new("", $key).Password
Remove-Variable key

$env:KROIKA_AI_PROVIDER = "gemini"
$env:KROIKA_ENABLED_AI_PROVIDERS = "mock,gemini"
$env:GEMINI_MODEL = "gemini-3.6-flash"
$env:GEMINI_API_MODE = "generate_content"
$env:GEMINI_THINKING_LEVEL = "minimal"
$env:KROIKA_AI_TIMEOUT_SECONDS = "300"

py -3.12 scripts/start_desktop.py
```

Провайдер и модель остаются настройками существующего бэкенда. Демо-режим и построение работают
локально, реальный анализ Gemini требует интернета. Ввод ключа в настройках окна — этап 2.

Подготовка без открытия окна:

```powershell
py -3.12 scripts/start_desktop.py --setup-only
```

Повторный запуск использует сборку, пока исходники, иллюстрации и конфигурация не изменились.
Для принудительной пересборки добавьте `--rebuild`. Для диагностики окна добавьте `--debug`.

Если новый архив распакован в другую папку, сначала сохраните незавершённые изменения в старой
веб-версии и закройте старый запуск. Затем укажите прежнюю папку `data`, заменив пример своим путём:

```powershell
py -3.12 scripts/start_desktop.py --data-dir "C:\Projects\Kroika-old\data"
```

Старые проекты и фотографии будут прочитаны из этой папки. Исходные файлы не нужно удалять или
перезаписывать. Если ранее заданы `KROIKA_DATABASE_PATH` / `KROIKA_IMAGE_STORAGE_PATH`, проверьте
их: эти переменные имеют приоритет над `--data-dir`.

## Данные и совместимость

- По умолчанию база — `data/kroika.db`, фотографии — `data/images`, как при обычном веб-запуске
  из этого репозитория. Существующие проекты, версии построений, история и профили мерок доступны
  сразу; форматы и схема базы не меняются.
- `KROIKA_DATABASE_PATH` и `KROIKA_IMAGE_STORAGE_PATH` имеют приоритет. Явную отдельную папку можно
  передать через `--data-dir "C:\KroikaData"`. Это выбор другого хранилища, а не копирование данных.
- Профиль окна хранится в `.local-state/desktop/webview`; приватный режим отключён. Последний
  открытый проект и локальные черновики доступны после перезапуска окна.
- Сохранённые в базе проекты доступны и вебу, и приложению. Несохранённые черновики старого
  браузера хранятся в профиле браузера и автоматически в окно не переносятся: сохраните их в
  веб-версии перед переходом. Перенос между установками и пользовательская папка — этап 2.
- Окно работает на постоянном адресе `http://127.0.0.1:18765`. Он нужен для стабильного хранилища
  черновиков. При занятом порте приложение показывает ошибку, а не подключается к чужому серверу.
  Можно явно задать `--port 18766`; локальные черновики относятся к конкретному адресу, поэтому
  порт после начала работы лучше сохранять прежним.
- Диалоги загрузки фотографий остаются доступными. Скачивание PDF/SVG/JSON разрешено в оболочке;
  на Windows WebView2 использует системный диалог сохранения. Подробная адаптация файлов — этап 2.
- Закрытие окна запрашивает подтверждение. Перед закрытием дождитесь завершения сохранения.
  Бэкенд получает сигнал остановки; зависший процесс завершается после ограниченного ожидания.
  Ошибка запуска или открытия окна также освобождает процесс и порт.
- Сервер слушает только loopback. Для окна проверяются Host и Origin; внешние сайты не получают
  разрешение CORS. API, загруженные изображения и экспорты обслуживаются раньше статических файлов.

## Проверка

```powershell
.venv\Scripts\python.exe -m pytest -q tests/test_desktop.py tests/test_verify_support.py
```

Тесты проверяют реальный запуск через `spawn`, общий адрес интерфейса/API, занятый порт,
ошибку базы, таймаут запуска, очистку при ошибке GUI, загрузку изображения, построение платья,
SVG/PDF, историю и сохранение проекта/профиля/фотографии после остановки и повторного запуска.
Настройки окна проверяются с подменённым GUI, без зависимости от графического окружения CI.
Workflow `.github/workflows/desktop.yml` запускает эти проверки и production-сборку интерфейса
на Windows и Linux. Он не считается проверкой настоящего графического окна.
Для коммита `9c99221` production-сборка и все 16 выбранных тестов прошли на обеих системах:
<https://github.com/Vechnoilive/Kroika/actions/runs/38159296328>.

Итоговая локальная регрессия: **774 passed, 55 subtests passed** по всему бэкенду и **133 passed**
по интерфейсу. TypeScript, production-сборка, Ruff по новым Python-файлам, `pip check` и подготовка
через `scripts/start_desktop.py --setup-only` прошли. Живой Gemini и настоящие графические
диалоги Windows в этой проверке не запускались.

Проверка на Windows вручную:

1. Откройте существующий проект и его результат, затем создайте новый проект в демо-режиме.
2. Подтвердите фасон, введите мерки, проверьте ткань и постройте лекала; откройте редактор и историю.
3. Загрузите фото и выполните анализ, если настроен Gemini; проверьте миниатюры и разбор деталей.
4. Сохраните PDF A4, проверочный лист, SVG и JSON; откройте сохранённые файлы.
5. Закройте окно и запустите снова: проект, результат и локальный черновик должны восстановиться.
6. Убедитесь, что после закрытия не осталось процесса бэкенда и порт снова доступен.

Графическое окно и системные диалоги требуют отдельной проверки на Windows. Успешные тесты
транспорта и подменённого GUI не заменяют эту проверку. Установщик, подпись и обновления пока
не входят в первый этап.
