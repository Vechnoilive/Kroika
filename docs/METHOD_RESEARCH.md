# Выбор методики и алгоритмов

Дата исследования: 2026-09-13. Решение относится к **исследовательскому этапу 2**, а не к сертификации посадки.

## Решение

Для первого вычислительного прототипа выбрана одна семья открытых параметрических блоков **GarmentCode**: прилегающий лиф с вытачками, fitted skirt и сопряжение рукава. Идентификатор исследовательской методики Kroika: `kroika-gc-woven`, версия `0.1.0`. Фиксированный исходник: commit `d449629979028123a5c4dc9e732a2ec19b7fce31` [официального репозитория](https://github.com/maria-korosteleva/GarmentCode/tree/d449629979028123a5c4dc9e732a2ec19b7fce31).

Основания выбора: доступные конкретные формулы, Python, разрешение MIT на использование кода, общая система для лифа/юбки/рукавов, явные интерфейсы стачивания. В научной работе описано построение одежды из параметрических компонентов; это соответствует требуемому разделению фасона и вычислений. [GarmentCode, ETH Zurich](https://igl.ethz.ch/projects/garmentcode/).

Это **не заявление**, что GarmentCode — самая распространённая школа конструирования или что её посадка лучше Aldrich/Мюллера на любой фигуре. Сопоставимого исследования, доказывающего такой рейтинг, в рассмотренных источниках нет. Выбор сделан по проверяемости реализации для нашего прототипа. Производственный выбор пока не закрыт.

## Что найдено при чтении кода GarmentCode

1. Исходник работает в **сантиметрах**, а Kroika должен работать в миллиметрах. Например, добавка к пройме `2.5` означает **25 мм**, порог `4` при распределении вытачек — **40 мм**. Без переноса всех размерных констант результат будет неверным.
2. `back_width` — **задняя дуга обхвата груди между боковыми линиями баланса**, а не привычная мерка «ширина спины между подмышечными складками». Подмена этих мерок испортит распределение переда и спинки. Определение проверено в авторском PDF [Body Measurements](https://github.com/maria-korosteleva/GarmentCode/blob/d449629979028123a5c4dc9e732a2ec19b7fce31/docs/Body%20Measurements%20GarmentCode.pdf).
3. В исходнике есть эмпирические доли `2/3`, `0.75`, `0.9`, коэффициент задней линии бёдер `1.05`. Они теперь перечислены явно. Это правила исходного блока, а не законы анатомии.
4. Часть исходных геометрических оптимизаторов при неуспехе печатает предупреждение и возвращает результат. Для Kroika это недопустимо: нужен статус ошибки и блокировка производственного экспорта.
5. Интерфейс стачивания может хранить коэффициент сборки/посадки. Совпадение такого интерфейса в симуляции не доказывает равенство бумажных длин. В платье без сборок остаток нужно измерять по реальным линиям шва.
6. В исходнике рукав составлен из передней и задней панелей. Это нельзя незаметно назвать базовым одношовным рукавом. Для MVP сначала проверяется платье без рукава; отдельная формализация одношовного рукава остаётся открытой частью этапа 2.

Снимки пяти изученных файлов и SHA-256 находятся в [manifest.json](../references/garmentcode/manifest.json). Они имеют расширение `.py.txt` и служат только источниками; приложение их не импортирует. Весь upstream не скопирован. Код построения, модель тела, датасет и симулятор не включены.

Помимо чтения кода, выполнен [аудит исходных геометрических заготовок](UPSTREAM_BLOCK_AUDIT.md) в отдельном окружении. Он подтвердил необходимость сравнивать реальные линии и учитывать посадку: сырые боковые швы юбки отличаются на 9.563–11.073 mm в трёх вычислительных профилях. Это промежуточные блоки, а не полный запуск готового платья.

## Численные алгоритмы для будущего движка

| Задача | Выбранное направление | Критерий корректности |
| --- | --- | --- |
| Кривые горловины/проймы | Кубические Безье; квадратичные при необходимости точно повышаются до кубических | Явные контрольные точки; проверка касательных; исходная кривая сохраняется |
| Длина кривой | Адаптивное интегрирование нормы производной или subdivision de Casteljau с верхней/нижней оценкой | Ошибка по всей паре швов укладывается в отдельный вычислительный бюджет |
| Сопряжение по длине | Ограниченный поиск корня Brent/bisection, если задача сведена к непрерывной монотонной скалярной функции | Есть допустимый интервал, смена знака либо точный корень на границе; проверены остаток и область, иначе ошибка |
| Несколько степеней свободы | Сначала явно ограничить семейство кривых; затем фиксированные старт/ограничения и проверка результата | «Оптимизатор завершился» недостаточно: отдельно измеряются шов, касательные и самопересечения |
| Перенос вытачки | Поворот сектора вокруг конструктивной вершины, затем уравнивание/оформление среза | Длины сторон после закрытия и сопряжение края проверяются |
| Самопересечения/площадь | Геометрическое ядро + Shapely/GEOS для контролируемо аппроксимированных контуров | Проверка до offset; нельзя молча исправлять исходную выкройку `buffer(0)` |
| Припуски | Отдельный offset контура с явными соединениями углов; Clipper2 рассматривается как кандидат | Контролируется погрешность аппроксимации и масштаб целочисленной сетки; разные припуски по рёбрам требуют отдельной обработки |
| Печать | Один канонический JSON, координаты mm, явное преобразование mm → PDF points | A4 210 × 297 мм, квадрат 50 мм, отсутствие масштабирования геометрии при раскладке |

Технические первоисточники: [Bézier, Pomax](https://pomax.github.io/bezierinfo/), [Brent — SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.brentq.html), [Shapely manual](https://shapely.readthedocs.io/en/stable/manual.html), [Clipper2 — авторская документация](https://www.angusj.com/clipper2/Docs/Overview.htm). Shapely не хранит гладкие кривые; Clipper2 использует целые координаты внутри даже при double-интерфейсе. Поэтому ни один из них не заменяет каноническую кривую Безье. Это выбор направлений для этапа 6, библиотеки ещё не установлены в проект.

## Что исследование не доказывает

Даже научная генерация большого числа синтетических изделий не является проверкой макета на реальной фигуре. [GarmentCodeData](https://igl.ethz.ch/projects/GarmentCodeData/) полезен как исследовательский ориентир, но его датасет, автоматические измерения тела и 3D-симуляция не нужны для текущего ручного ввода мерок.

Три наших профиля — искусственные контрольные числа для проверки формул. Они не являются ответами тёти, реальными клиентами, размерной сеткой или подписанными ручными построениями.
