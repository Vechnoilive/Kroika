# Локальный запуск Kroika

Этап 5 запускается без API-ключей. Вместо Qwen используется подписанный `mock`, а проекты и явно сохранённые профили мерок находятся только в локальной SQLite.

## Самый простой способ без Docker

Установите Python 3.12+, Node.js 24+ и Git. Откройте терминал в корне `Kroika` и выполните одну команду.

Windows PowerShell:

```powershell
py -3.12 scripts/start_local.py
```

macOS/Linux:

```bash
python3 scripts/start_local.py
```

При первом запуске скрипт создаст `.venv`, установит зафиксированные зависимости, запустит backend и frontend и откроет `http://127.0.0.1:5173`. Последующие запуски не переустанавливают зависимости, пока lock-файлы не изменились. Для остановки нажмите `Ctrl+C` один раз.

Полезные варианты:

```bash
python3 scripts/start_local.py --setup-only
python3 scripts/start_local.py --no-browser
```

В Windows замените `python3` на `py -3.12`.

## Docker Compose

Если установлен Docker Desktop или Docker Engine с Compose:

```bash
docker compose up --build
```

- интерфейс: `http://localhost:8080`;
- API: `http://localhost:8000`;
- документация FastAPI: `http://localhost:8000/docs`;
- готовность: `http://localhost:8000/health/ready`.

Остановка:

```bash
docker compose down
```

Данные проектов остаются в именованном томе `kroika-data`. Команда `docker compose down -v` удалит их, поэтому без необходимости `-v` не используйте.

## Полная проверка

После подготовки окружения выполните `.venv/bin/python scripts/verify_all.py` на macOS/Linux или `.venv\Scripts\python.exe scripts\verify_all.py` в Windows PowerShell.

Команда проверяет этапы 2–5, backend API, SQLite, правила мерок, frontend-тесты, TypeScript, production build и smoke-сценарии.

## Частые проблемы

| Сообщение | Что сделать |
| --- | --- |
| «Не найден Node.js/npm» | Установить Node.js 24, закрыть и заново открыть терминал |
| Порт 5173 или 8000 занят | Остановить предыдущий запуск `Ctrl+C`; проверить, что другое приложение не использует порт |
| PowerShell запрещает скрипты активации | Активация не нужна: `start_local.py` сам вызывает Python из `.venv` |
| Интерфейс пишет «Нет связи» | Подождать несколько секунд и обновить страницу; открыть `/health/ready` |
| Нужно полностью повторить установку | Удалить только `.venv`, `frontend/node_modules` и `.local-state`, затем снова выполнить команду запуска |

## Что уже можно проверить руками

1. Создать проект и увидеть его в списке недавних.
2. Закрыть и открыть страницу — последний проект восстановится из SQLite.
3. Запустить mock-анализ демонстрационного эскиза.
4. Ввести несколько мерок по одной, переключить cm/mm и увидеть мгновенную проверку диапазона.
5. Сохранить черновик, обновить страницу и продолжить с сохранённых значений.
6. По отдельному флажку сохранить профиль и открыть его в другом проекте.

Методика всё ещё имеет статус `experimental`: сохранённые реальные мерки пока нельзя превращать в производственную выкройку. Геометрия начинается на этапе 6, Qwen — на этапе 10.
