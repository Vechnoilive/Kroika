# Кройка для ПК — настройки, проекты и файлы

Готовый установщик без Python/Node и обновления описаны в [третьем этапе](DESKTOP_STAGE3.md). Команды ниже относятся к запуску из исходников.

## Запуск

Из корня актуального репозитория, Windows PowerShell:

```powershell
py -3.12 scripts/start_desktop.py
```

На этом этапе ещё нужны Python 3.12+, Node.js 24+ и Microsoft Edge WebView2 Runtime. Установщик
без среды разработки относится к третьему этапу. Зависимости и интерфейс готовит launcher.

## Gemini без команд настройки

Откройте **«Настройки приложения»** в верхней панели. Выберите Gemini, укажите модель и вставьте
API-ключ. Нажмите **«Применить настройки»**, затем по необходимости проверьте подключение.
В версии 0.3.1 подключение доступно также кнопкой **«Подключить Gemini»** прямо на экране
фотографий: сервис уже выбран и поле ключа получает фокус. После сохранения закройте настройки,
откройте снимки, укажите перед/спинку, подтвердите отправку и запустите анализ.
В дополнительных параметрах доступны размышление, время ожидания, максимум выходных токенов,
число попыток и режим API. Ноль секунд отключает таймаут ответа AI; число повторов остаётся
ограниченным. Проверка соединения отправляет короткий текст без фотографий и может расходовать
лимит API. Фотографии отправляются по прежнему явному согласию на экране анализа.

Изменения применяются к новым запросам сразу, без перезапуска окна и сброса проекта. Уже начатый
запрос сохраняет выбранный экземпляр провайдера. Настройки, сохранённые в приложении, имеют
приоритет над моделью/провайдером/таймаутом из окружения. До первого сохранения действуют прежние
переменные окружения; регион Qwen и адрес API Gemini остаются настройками окружения.

На Windows ключ хранится в Windows Credential Manager через keyring. В JSON настроек записывается
только ссылка на запись. Исходный ключ не возвращается в интерфейс, не попадает в проекты,
резервные копии, localStorage или журнал запросов. Поле ключа остаётся пустым: пустое значение
сохраняет текущий ключ, новый текст заменяет его. Отдельная галочка удаляет ключ при применении.
Удаление отключает также повторное подхватывание прежнего ключа из окружения.

Если системное хранилище недоступно, новый ключ можно использовать только в текущем сеансе:
приложение сообщает об этом и не сохраняет его в файл. На macOS используется Keychain, на Linux
— Secret Service при его наличии. Произвольные сторонние и файловые keyring backends не выбираются.
При ошибке записи настроек прежняя конфигурация восстанавливается. Если системное хранилище
не позволило удалить старую запись, интерфейс сообщает об этом отдельно; запись перестаёт
использоваться приложением.

## Постоянная папка данных

По умолчанию приложение использует:

| Система | Папка приложения |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Kroika` |
| macOS | `~/Library/Application Support/Kroika` |
| Linux | `$XDG_DATA_HOME/kroika` или `~/.local/share/kroika` |

Внутри: `data/kroika.db`, `data/images`, профиль окна `webview`, настройки `settings.json`,
журналы `logs`, проверенные исходные копии импорта `backups`. Обновление или повторная распаковка
репозитория не меняет эту папку. Найти данные и журналы можно кнопками в настройках приложения.
Журнал содержит метаданные запросов и коды ошибок; файлы ограничены размером и ротируются.

`--data-dir` и `KROIKA_DATABASE_PATH` / `KROIKA_IMAGE_STORAGE_PATH` продолжают поддерживаться;
переменные окружения имеют приоритет над `--data-dir`. Это явный выбор рабочего хранилища,
а не команда копирования. `KROIKA_DESKTOP_HOME` меняет папку настроек/профиля/журналов для
изолированного теста. По умолчанию адрес окна сохраняется `http://127.0.0.1:18765`; менять порт
после начала работы не рекомендуется, поскольку черновики привязаны к адресу.

Веб-версия продолжает использовать прежнюю папку репозитория. Если нужны общие данные веба и
приложения, явно задайте одинаковые пути базы и изображений. Перенесённая копия сама по себе
не синхронизирует последующие изменения старой веб-версии.

## Перенос прежних проектов

Перед переходом сохраните незавершённые изменения в старой веб-версии и закройте прежнее окно
приложения. При первом запуске с пустым пользовательским хранилищем данные из `data` текущего
репозитория переносятся автоматически. Прежний профиль окна первого этапа копируется отдельно,
чтобы сохранить его локальные черновики. Исходная папка остаётся на месте.

Если архив распакован в другую папку или пользовательское хранилище уже заполнено, используйте
**«Настройки приложения → Импортировать проекты из папки»**. Выберите прежнюю папку `data` либо
корень старого репозитория. Импорт доступен после сохранения текущих изменений проекта.

Переносятся проекты, все версии построений, история правок, снимки входов, физические проверки,
профили мерок и фотографии. Снимок SQLite создаётся через backup API, включая данные WAL;
проверяются целостность, ссылки и наличие фотографий. Проверенная исходная копия остаётся в
`backups`. Повторный импорт идентичных записей не создаёт дубликаты. При одинаковых ID с разными
данными либо нарушении связей импорт останавливается: существующие записи не перезаписываются,
новые записи и фотографии откатываются. Импорт не объединяет изменённые версии одинакового ID.

Несохранённые черновики старого браузера принадлежат профилю браузера: их нужно сохранить в
веб-версии перед переносом. Ключи, настройки и браузерные черновики другого компьютера импорт
папки проектов не включает. Импортируемая SQLite-база должна иметь поддерживаемую версию схемы.

## Файловые действия

- Фото открываются кнопкой **«Открыть фотографии с компьютера»** через системный диалог. Далее
  сохраняются прежние миниатюры, роли переда/спинки, порядок, поворот и согласие на отправку.
- PDF A4, проверочный лист, SVG, JSON проекта и отчёт физической проверки сохраняются через
  системный диалог. Запись атомарна; отмена диалога не создаёт файл и не вызывает повторный веб-экспорт.
- Экспорт не может перезаписать рабочую базу, её WAL/SHM, настройки, фотографии или профиль окна.
- В обычном веб-запуске сохраняется браузерная загрузка и скачивание файлов; desktop-кнопки скрыты.

Одновременно открыть два приложения с одним профилем нельзя. Порт резервируется до переноса
данных, чтобы второй запуск не начал копирование профиля уже работающего окна. Native bridge
принимает действия только от главной страницы своего окна; служебные HTTP-действия требуют
отдельного токена процесса, который не включается в UI или файлы.

## Проверки

```powershell
.venv\Scripts\python.exe -m pytest -q tests/test_desktop.py tests/test_desktop_stage2.py tests/test_verify_support.py
```

Проверяются применение AI-настроек без перезапуска, защита ключа и откат при ошибке записи,
системное хранение ключа на Windows, перенос реального построения с фото/историей/профилями и
физическими проверками, повторный импорт, конфликт ID, нехватка фото, поздняя ошибка SQL,
системное сохранение, отмена и защита файлов приложения. Workflow `desktop.yml` запускает эти
тесты, production-сборку и весь UI suite на Windows/Linux. Графические диалоги подменяются в
тестах; реальное взаимодействие с окном, файловым диалогом и живым Gemini проверяется отдельно
на Windows. Установщик, подпись и обновления входят в третий этап.
