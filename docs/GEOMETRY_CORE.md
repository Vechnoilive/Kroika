# Ядро вычислительной геометрии

Версия ядра: `0.1.0` · пакет: `kroika_pattern_engine.geometry` · этап: 6/15.

Ядро — независимая pure-Python библиотека без FastAPI, SQLite и AI SDK. Оно предоставляет математические операции для будущих блоков выкройки, но само не содержит формул лифа, юбки или рукава.

## Числовая модель

- Внутренние числа — Python `float`, то есть IEEE-754 binary64.
- Все координаты, расстояния, длины и допуски имеют суффикс `_mm` и трактуются только как миллиметры.
- Площади возвращаются в `mm²`.
- Углы внутри ядра — радианы; JSON-контракт SVG-подобной дуги использует градусы.
- `NaN`, `Infinity`, логические и строковые координаты отклоняются при создании объекта.
- Политика по умолчанию: абсолютный допуск `1e-8 mm`, относительный `1e-12`, линеаризация кривой `0.001 mm`, не более 24 уровней деления.
- Поддерживаемая координатная область — `±1 000 000 000 mm`; выход за неё блокируется до операций, способных переполнить binary64.

## Реализованные операции

| Объект / операция | Реализация и точность |
| --- | --- |
| `Point`, `Vector`, `BoundingBox` | Расстояния, скалярное/векторное произведение, нормаль, границы |
| `LineSegment` | Точная длина, точка/касательная по параметру, преобразования |
| `ArcSegment` | Круговая или повёрнутая эллиптическая дуга, SVG endpoint ↔ centre, длина с адаптивным контролем ошибки |
| `CubicBezier` | De Casteljau, деление, экстремумы, длина через адаптивную линеаризацию |
| `Contour` | Проверка соединений, длина, точная ориентированная площадь линий/Безье/эллиптических дуг, направление и границы |
| Пересечения | Аналитические line/line и line/ellipse; остальные пары — детерминированная линеаризация с явным `flatness_mm` |
| Offset | Точный для линии и круговой дуги; общий простой замкнутый контур — полилиния с `miter`/`bevel` и проверкой результата |
| Преобразования | Перенос, поворот, отражение, равномерное и неравномерное масштабирование; дуга сохраняется дугой только при similarity-transform |
| Сериализация | Строгий путь из `pattern-data.schema.json`, канонический UTF-8 JSON, сортировка ключей, round-trip |

Положительный `offset_contour` всегда направлен наружу независимо от обхода контура; отрицательный — внутрь. У направленного отдельного отрезка/дуги положительный `distance_left_mm` означает смещение влево.

## Ошибки без скрытого исправления

Все ошибки наследуются от `GeometryError`, имеют стабильный машинный `code` и нейтральное русское сообщение. Отдельно различаются неверная координата/параметр, вырожденная геометрия, разорванный или открытый контур, неоднозначное перекрытие, самопересечение, схлопнувшийся offset, неподдержанная точная операция и недостижимая точность.

Ядро намеренно не:

- заменяет нечисловые или бесконечные значения нулём;
- выбирает одну точку из коллинеарного перекрытия;
- исправляет самопересечения offset автоматически;
- выдаёт неравномерно преобразованную окружность за круговую дугу;
- выдаёт аппроксимацию эллиптического offset за точный эллипс;
- строит полный эллипс одной SVG-дугой — для него нужны минимум две дуги.

## Ручные корректировки этапа 27

Модуль `kroika_pattern_engine.manual_edit` применяет только ограниченные изменения уже существующего контура: перенос конечного узла сегмента или управляющей точки кубической кривой. Общая вершина обновляется сразу у обоих соседних сегментов, поэтому контур не разрывается из-за различающихся координат.

После набора правок модуль повторно проверяет простой замкнутый контур, минимальную площадь, положение надсечек и фактические длины всех `seam_pairs`, затем заново строит припуски. Линии сгиба защищены, одно перемещение ограничено 50 мм, а добавление/удаление сегментов не поддерживается. Правка всегда сохраняется отдельной генерацией и не меняет рассчитанный исходник.

## Границы этапа

Общий offset и пересечения сложных кривых используют полилинейную аппроксимацию с заданным пределом. Если после offset контур самопересёкся, схлопнулся или вывернулся, операция блокируется. Булевы операции над произвольными областями, удаление петель offset и припуски по типам швов относятся к этапу 9.

Геометрическое ядро не подтверждает методику посадки. На этапе 6 результат /patterns/generate возвращал BASE_BLOCKS_STAGE_NOT_READY. С этапа 7 блоки выполняются отдельным слоем, но публичный результат остаётся rejected и pattern=null с GARMENT_ASSEMBLY_STAGE_NOT_READY до безопасной сборки изделия на этапе 8.

## Проверка

```bash
.venv/bin/python scripts/verify_stage6.py
```

Gate содержит обычные и property-based тесты: инварианты преобразований, симметрию пересечений, формулы площади и offset прямоугольника, граничные/вырожденные случаи, топологию, канонический JSON и интеграционную диагностику. Зафиксированный fingerprint расположен в [geometry-diagnostic.json](../references/stage6/geometry-diagnostic.json).
