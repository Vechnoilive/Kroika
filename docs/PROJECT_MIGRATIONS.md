# Версии и миграции проектов

`PatternProject 1.0.0` — первый опубликованный формат проекта Kroika. До этапа 3 сохраняемого `PatternProject` не существовало, поэтому миграция из выдуманного старого формата не добавляется.

## Четыре независимые версии

| Поле | Что меняется | Пример |
| --- | --- | --- |
| `schema_version` | Структура JSON проекта | `1.0.0` |
| `revision` | Пользовательское сохранение одного проекта | `1`, `2`, `3` |
| `pattern_method.version` | Формулы и правила построения | `0.1.0` |
| `engine_version` | Реализация вычислительного движка | `0.12.0` |

Повышение одной версии не изменяет остальные автоматически. Открытие старого проекта не пересчитывает геометрию по новой методике. Пересчёт создаёт новую запись `generation_history` с новым hash.

## Правила миграции

1. Сначала прочитать исходные байты и сохранить резервную копию.
2. Определить `schema_version`; при её отсутствии остановиться с понятной ошибкой.
3. Проверить наличие непрерывного пути миграций до текущей версии.
4. Применять каждый переход к глубокой копии, не меняя входной объект.
5. Проверить целевую JSON Schema и смысловые инварианты.
6. Сохранить как новую ревизию; исходную копию и журнал переходов оставить доступными для восстановления.

[migrations.py](../src/kroika_contracts/migrations.py) реализует реестр последовательных переходов, защиту от циклов и отказ для неизвестной версии. Сейчас production-реестр пуст: `1.0.0` уже текущая версия. Тестовый двухшаговый переход проверяет сам механизм без объявления фиктивного старого формата проекта.

При появлении `1.1.0` или `2.0.0` вместе с изменением добавляются функция `old → new`, фикстура старого проекта, ожидаемый результат и проверки повторяемости. Удаление неизвестных полей, догадка о единицах и заполнение обязательной мерки средним значением запрещены. Если безопасного перехода нет, проект открывается только для чтения и предлагает экспорт исходного JSON.

## Версия локальной базы

SQLite использует независимый `PRAGMA user_version`; текущая версия — `1`. При
открытии базы с более новой неизвестной версией приложение останавливается,
чтобы не повредить данные. Перед миграцией или заменой базы обязательна
проверяемая резервная копия по [BACKUP_AND_RECOVERY.md](BACKUP_AND_RECOVERY.md).
