# Контракт AI-провайдеров

Этап 3 спроектировал общий интерфейс. На этапе 4 реализован детерминированный offline mock-адаптер; сетевые вызовы Qwen/Gemini появятся на этапе 10.

## Безопасная граница

`AIProvider.analyze_style()` получает [AIAnalysisRequest](../schemas/v1/ai-analysis-request.schema.json): 1–4 непрозрачных `image_ref`, язык, поддержанные категории и признаки, а также подтверждение передачи изображения. Схема не содержит `BodyMeasurements`, прибавок, припусков или координат. Неизвестное поле с мерками отклоняется.

Провайдер возвращает [AIStyleAnalysis](../schemas/v1/ai-style-analysis.schema.json). Все верхнеуровневые поля обязательны, неизвестные поля запрещены, `confidence` ограничен от 0 до 1. Невидимые признаки записываются как `unknown`, `uncertainties` и вопросы. Гипотеза ткани всегда имеет `must_confirm=true`.

После ответа выполняются четыре шага:

1. Адаптер преобразует vendor-specific structured output в общий JSON.
2. Backend проверяет строгую схему и смысловые противоречия.
3. Пользователь видит предложение, исправляет и подтверждает его.
4. Backend создаёт отдельный подтверждённый `GarmentSpec`; сам AI-ответ в Pattern Engine не передаётся.

Исходный ответ провайдера допускается хранить только в ограниченном диагностическом журнале с политикой удаления. В проект попадает нормализованное предложение и ссылка на анализ, без ключей и Base64 изображений.

## Общий интерфейс

Интерфейс [AIProvider](../src/kroika_contracts/ports.py) асинхронный и не зависит от SDK. Будущие адаптеры: `mock`, `qwen`, `gemini`. Каждый адаптер отвечает за формат запроса конкретного API, таймаут, ограниченный повтор и перевод ответа в общую схему.

Ошибки имеют один из кодов:

| Код | Что увидит пользователь | Повтор |
| --- | --- | --- |
| `timeout` | «Сервис не успел ответить. Попробуйте ещё раз или заполните фасон вручную» | Один контролируемый повтор |
| `auth` | «Провайдер не настроен. Доступен ручной режим» | Только после настройки |
| `rate_limit` | «Лимит запросов исчерпан. Данные проекта сохранены» | По разрешённому времени |
| `invalid_schema` | «Ответ не удалось проверить. Подтвердите фасон вручную» | Один исправляющий запрос |
| `provider_unavailable` | «Провайдер недоступен. Выберите другой или ручной режим» | При смене провайдера |

На один ответ допускается максимум один исправляющий запрос. После повторной ошибки открывается ручной редактор, а черновик сохраняется. Выбор основного реального провайдера будет сделан после единой оценки минимум на 50 разрешённых изображениях.
