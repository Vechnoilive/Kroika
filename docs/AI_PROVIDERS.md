# Контракт AI-провайдеров

Архитектура содержит три взаимозаменяемых адаптера: `QwenProvider`, `GeminiProvider` и
полностью локальный `MockVisionProvider`. Интерфейс показывает только адаптеры из
`KROIKA_ENABLED_AI_PROVIDERS`; без явной настройки обязательным остаётся безопасный mock.
Pattern Engine от провайдеров не зависит и не получает сырой ответ модели.

## Безопасная граница

Внешний провайдер получает только байты 1–4 изображений, допустимые категории и
словарь признаков. `request_id`, `project_id`, мерки, прибавки, припуски и координаты не
включаются в vendor payload. API-ключи читаются только backend из окружения и не
возвращаются в status API или браузер.

JPEG, PNG и WebP до 10 МБ проверяются по фактической сигнатуре, сохраняются локально
под случайным `img_*`, и только затем могут быть переданы выбранному сервису. Интерфейс
требует отдельное согласие именно для внешнего адаптера. Mock не читает и не отправляет
файл.

Этап 23 позволяет подписать каждый файл как вид спереди, сзади, сбоку, крупную деталь
или плоский эскиз. В prompt попадают только номер и enum подписи; локальный `image_ref`
не передаётся. Успешно загруженные ссылки переиспользуются после таймаута или отмены,
пока открыт текущий шаг.

Кнопка «Проверить соединение» выполняет только явный text-only запрос с лимитом ответа
8 токенов. Фото и мерки не отправляются, но запрос может учитываться провайдером в
квоте. Автоматически и во время открытия страницы проверка не запускается.

## Запрос и строгий ответ

Общий system prompt запрещает модели оценивать тело, размеры, скрытые детали,
припуски и геометрию. Для невидимого признака требуются `unknown`/`uncertain`,
пониженная уверенность, неопределённость и точный вопрос на русском.

С этапа 16 новый ответ обязан содержать `design_features`: отдельные элементы фасона
(пояс, складка, волан, панель, драпировка, карман и т. п.), слои ткани и визуальные
пропорции. Для каждой детали сохраняются расположение, способ соединения, уверенность и
доказательство на изображении. Поле остаётся необязательным только в канонической схеме
хранения, чтобы ранее сохранённые проекты продолжали открываться; provider schema требует
его для каждого нового внешнего ответа.

Qwen вызывается через официальный OpenAI-compatible vision endpoint с multimodal
`image_url`. Gemini по умолчанию использует официальный `generateContent` REST API
с inline base64 и JSON-режимом для одного разового анализа. Он не создаёт сохранённый
Interaction или цепочку разговоров; обработка данных всё равно подчиняется условиям
Google и выбранному тарифу. Через `GEMINI_API_MODE=interactions` доступен прежний API,
которому явно передаётся `store=false`. Автоматического переключения API или модели нет.
Полная каноническая схема
передаётся Gemini один раз в инструкции, но не дублируется в `response_format`: Google
может отклонять слишком большие или глубоко вложенные Structured Output схемы. Для
Gemini 3.x температура не занижается принудительно: используется рекомендуемое моделью
значение по умолчанию. После любого сервиса backend независимо выполняет:

1. JSON-разбор без `NaN`/`Infinity`, лишнего текста и ответов больше 256 КБ.
2. Проверку `ai-style-analysis.schema.json`, включая enum и запрет лишних полей.
3. Semantic validation против взаимоисключающих признаков и бездоказательного `ok`.
4. Проверку уникальных ID деталей, ровно одного основного слоя и вопроса для каждой
   сомнительной конструктивной особенности.

Официальные основания реализации: [Qwen VL OpenAI-compatible vision](https://www.alibabacloud.com/help/en/model-studio/qwen-vl-compatible-with-openai), [Gemini Interactions и retention](https://ai.google.dev/gemini-api/docs/interactions-overview), [Gemini image input](https://ai.google.dev/gemini-api/docs/image-understanding), [Gemini structured output](https://ai.google.dev/gemini-api/docs/structured-output) и [доступные регионы Gemini](https://ai.google.dev/gemini-api/docs/available-regions). Региональные ограничения не обходятся; Qwen key и endpoint должны принадлежать одному региону.

## Отказы без ложного успеха

Таймауты 408/504, сетевой сбой, временный 429 и 5xx повторяются не более настроенного
лимита (по умолчанию три вызова всего). Между попытками используется экспоненциальная
пауза с небольшим jitter: для Gemini от пяти секунд, для Qwen от одной секунды.
Учитываются `Retry-After` и `google.rpc.RetryInfo` с пределом паузы 60 секунд.
Исчерпанная дневная квота (`quota_exceeded`) не повторяется автоматически.
Авторизация, неверная конфигурация, неверное
изображение и невалидный ответ не повторяются; для отклонённого endpoint/model интерфейс
предлагает проверить API-ключ, адрес API и имя модели. HTTP API возвращает стабильные
коды 422/429/503/504. UI сохраняет проект и изображение и предлагает явный переход в
demo/mock. Он никогда не выдаётся за анализ загруженного фото.

На одну попытку по умолчанию отводится 300 секунд ожидания ответа. Переменная
`KROIKA_AI_TIMEOUT_SECONDS` принимает 1–1800 секунд; `0` отключает лимит чтения ответа.
Соединение ограничено 30 секундами, отправка запроса — 60 секундами (или меньшим
заданным таймаутом). Несколько попыток могут увеличить общее время ожидания.
Фронтенд не прерывает анализ по таймеру, показывает прошедшее время и позволяет отменить
ожидание. Отмена в браузере не гарантирует отмену уже отправленного запроса у провайдера.

Gemini 3.x получает `low` для анализа. Проверка соединения использует `minimal` только
для известных поддерживающих его моделей, иначе `low`. В частности, 3.7 и 3.8 Flash
не поддерживают `minimal`; прежняя универсальная настройка была несовместима с ними.
Для Gemini 2.5 Flash через `generateContent` используется `thinkingBudget`, а не
`thinkingLevel`: 0 для проверки соединения и 1024 для анализа. Доступ к 2.5 ограничен
проектами с историей использования этой модели, поэтому для нового проекта она не
предлагается как основной вариант.

`GEMINI_MAX_OUTPUT_TOKENS` задаёт бюджет анализа: по умолчанию 16384, допустимо
1024–65536. Это потолок, включая thinking, а не размер каждого ответа. Маленького
ограничения выходных токенов у текстовой проверки нет. Ответ `generateContent`
принимается только с `finishReason=STOP`; `MAX_TOKENS` и блокировки отвергаются, даже
если текст выглядит как правильный JSON. Thought-части не используются как результат.
Незавершённый Interaction также не принимается, даже если в нём есть текст.
Ответ `status=failed` разбирается как ошибка API.
Успешная текстовая проверка соединения не гарантирует успешный разбор изображения.

Событие `ai_provider_attempt_failed` содержит только метаданные: `request_id`,
`provider_id`, `model`, `api_mode`, HTTP-статус провайдера (`upstream_status`), известный код ошибки
(`upstream_code`), тип сетевого исключения, попытку, время и паузу перед повтором.
Событие `ai_request_failed` связывает итоговый отказ с кодом обращения в UI.
Тексты ответов API, промпты, фото и ключи не попадают в логи. HTTP 503 нашего приложения
может означать сетевую ошибку или отказ внешнего API; точную причину показывают эти события.
Коды и формат ошибок сверены с [Gemini API errors](https://ai.google.dev/gemini-api/docs/api-errors),
повторы — с [troubleshooting](https://ai.google.dev/gemini-api/docs/troubleshooting).

## Настройка

Без ключей безопасный default — `KROIKA_AI_PROVIDER=mock`. Для внешнего сервиса задайте
только на backend:

```dotenv
KROIKA_AI_PROVIDER=qwen
QWEN_API_KEY=...
QWEN_BASE_URL=https://WORKSPACE.REGION.maas.aliyuncs.com/compatible-mode/v1
QWEN_MODEL=qwen3-vl-plus
```

Список вариантов интерфейса задаёт `KROIKA_ENABLED_AI_PROVIDERS`, например
`mock,qwen` или `mock,gemini`. Gemini включается только явным изменением этого списка;
VPN и другие способы обхода региональных ограничений не используются. Сервер запускается
и при неполной внешней конфигурации, чтобы mock-сценарий не был заблокирован.

Пример Windows PowerShell для рекомендуемой Gemini 3.8 Flash (ключ уже задан в этой консоли):

```powershell
$env:KROIKA_AI_PROVIDER = "gemini"
$env:KROIKA_ENABLED_AI_PROVIDERS = "mock,gemini"
$env:GEMINI_BASE_URL = "https://generativelanguage.googleapis.com/v1beta"
$env:GEMINI_MODEL = "gemini-3.8-flash"
$env:GEMINI_API_MODE = "generate_content"
$env:GEMINI_MAX_OUTPUT_TOKENS = "16384"
$env:KROIKA_AI_TIMEOUT_SECONDS = "600"
$env:KROIKA_AI_MAX_ATTEMPTS = "3"
py -3.12 scripts/start_local.py
```

Для ожидания ответа без лимита вместо `600` задайте `0`.

### Выбор модели и отдельная диагностика

На 06.10.2026 кандидат для сложной одежды — 3.8 Flash, альтернатива — 3.6 Flash,
экономный вариант для простых изделий — 3.5 Flash-Lite. Это инженерная рекомендация
по опубликованным возможностям, а не доказанный рейтинг на фотографиях Kroika.
Все три модели принимают изображения и structured output; пределы — 1048576 входных
и 65536 выходных токенов. Схема Kroika занимает около 9.7 тысяч символов; точное число
токенов зависит от модели и приложенных изображений. Небольшой текстовый probe не
проверяет обработку изображения, полноту деталей или правильность лекал.

| Модель | Роль | Standard USD за 1M входных / выходных токенов на 06.10.2026 |
|---|---|---|
| `gemini-3.8-flash` | Основной кандидат для сложных деталей | 0.75 / 3.75 до 31.12.2026 |
| `gemini-3.6-flash` | Альтернатива при отказе 3.8 | 0.75 / 3.75 до 31.12.2026 |
| `gemini-3.5-flash-lite` | Экономный предварительный разбор | 0.30 / 2.50 |
| `gemini-3.5-flash` | Ранее выбранная модель | 1.50 / 9.00 |

Источники: [модели](https://ai.google.dev/gemini-api/docs/models),
[thinking](https://ai.google.dev/gemini-api/docs/thinking),
[цены](https://ai.google.dev/gemini-api/docs/pricing). Указанные цены не определяют
доступную конкретному ключу квоту или надёжность endpoint.

Проверка доступности без запуска веб-сервера:

```powershell
.\.venv\Scripts\python.exe scripts/check_gemini.py
```

Скрипт делает по одному короткому текстовому запросу для каждой из трёх моделей через
оба API (всего шесть), без фото, мерок, автоматических повторов и вывода ключа. Можно
сузить проверку, например:

```powershell
.\.venv\Scripts\python.exe scripts/check_gemini.py --models gemini-3.8-flash --api-modes generate_content
```

Успех одного API при отказе другого помогает локализовать проблему endpoint;
отказы нескольких моделей с HTTP 503 указывают на проблему сервиса или маршрута к нему.
Это не основание обходить ограничения доступа и не гарантия качества анализа.

## Evaluation и выбор default

`evaluation/stage10` содержит 50 собственных CC0 синтетических схем с seed-разметкой.
`scripts/evaluate_stage10.py` одинаково считает для Qwen/Gemini schema/semantic validity,
точность каждого признака, полноту вопросов, Brier score уверенности, latency и cost.

Синтетика проверяет интеграцию, но не качество на реальной одежде. Переключение default
на автоматический внешний default остаётся заблокированным до проверки минимум на 50
разрешённых реальных изображениях со статусом `expert_verified`. Qwen или Gemini можно
включить вручную для локального запуска, но без ключа `mock` остаётся безопасным
операционным default. Это решение о доступности, а не заявление о доказанном качестве.
