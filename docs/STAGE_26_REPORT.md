# Отчёт этапа 26 — сравнение генераций

Дата: 2026-09-24. Версии frontend/backend: `0.26.0`; геометрический движок остаётся
`kroika-geometry 0.12.0`, потому что формулы построения не менялись.

## Что реализовано

- Каждая новая генерация получает неизменяемый локальный снимок точных входов: методики,
  мерок, фасона, прибавок, припусков и ткани. Снимок удаляется каскадно вместе с проектом.
- Для существующих генераций снимки безопасно восстанавливаются из ревизий проекта, только
  когда ревизия прямо ссылается на этот `generation_id`. Недостающие данные не угадываются.
- API возвращает список генераций проекта и детерминированный diff только двух версий
  одного проекта.
- Интерфейс по умолчанию сравнивает предыдущую генерацию с текущей, позволяет выбрать или
  поменять версии местами и показывает два настоящих SVG рядом.
- Отдельно показаны изменения мерок; фасона, прибавок и ткани; добавленные/удалённые детали;
  дельты площади, ширины, высоты и периметра контуров; изменения листов A4 и предупреждений.

## Проверка этапа

```bash
.venv/bin/python scripts/verify_stage26.py
```

Gate запускает только проверки этапа 26:

- 5 Python-тестов API, реального изменения геометрии, изоляции проектов, fail-closed
  поведения, восстановления снимков, OpenAPI и wiring;
- 2 UI-теста выбора/перестановки версий и состояния до второй генерации;
- Ruff только для затронутого Python-кода;
- TypeScript typecheck и production-сборку Vite.

Старые тест-наборы и live-запросы Qwen/Gemini не запускаются.

## Ограничения

Сравнение показывает причинно связанные входы и численные изменения контуров, но не
доказывает посадку. Решение, какая версия лучше, остаётся за конструктором после бумажной
проверки и макета. Для очень старой генерации без точной ревизии Kroika честно отключит
сравнение вместо реконструкции предположительных мерок.
