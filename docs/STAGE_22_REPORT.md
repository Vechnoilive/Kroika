# Отчёт этапа 22 — журнал физической приёмки

Дата: 2026-09-23. Версии frontend/backend: `0.22.0`; геометрический движок остаётся `kroika-geometry 0.12.0`, потому что формулы и каноническая геометрия на этом этапе не менялись.

## Что реализовано

- SQLite мигрирован до schema version 2; добавлена отдельная append-only таблица физических наблюдений с каскадным удалением вместе с проектом.
- `GET/POST /api/v1/patterns/{generation_id}/physical-validation` возвращают журнал и добавляют запись только к существующей успешной генерации.
- Поддержаны три независимых gate: `paper`, `expert`, `toile`.
- Бумажный результат нельзя назначить вручную: он выводится из квадрата 50×50 мм и линии 200 мм при рабочем физическом допуске ±1 мм.
- Для открытия допуска точной версии нужны две успешные записи разных принтеров, последнее положительное заключение конструктора и три успешных макета на разных профилях фигур.
- Более новая отрицательная запись снимает допуск. Исправление добавляется новой записью; история не редактируется и не удаляется через API.
- Записи одной генерации не влияют на другую, даже если обе принадлежат одному фасону или используют одинаковые мерки.
- SVG/PDF остаются диагностическими до закрытия gate. После закрытия заголовки ответа и содержимое экспорта получают `production-ready=true`; экспериментальный watermark убирается только у этой генерации.
- На шаге результата добавлена форма журнала, прогресс `1/2` и `1/3`, история наблюдений и понятное предупреждение.
- Явная кнопка «Назад» теперь показывается на всех шагах 2–7; возврат со второго шага ведёт к списку проектов и не удаляет сохранённый проект.

## Fail-closed правила

1. Проверка отклонённого построения запрещена.
2. Один принтер не закрывает бумажный gate; повтор того же имени принтера не считается второй установкой.
3. Один профиль фигуры не может закрыть три макета повторными строками.
4. `failed` требует текст замечания.
5. Макет требует явный профиль/обозначение фигуры.
6. Новая генерация начинает журнал с `pending/pending/pending`.
7. Автоматические тесты работают во временной базе и не создают реальных подписей или фиктивных пользовательских проверок.

## Проверка этапа

```bash
.venv/bin/python scripts/verify_stage22.py
```

Gate запускает только проверки этапа 22:

- 5 Python-тестов API, миграции SQLite v1→v2, расчёта допуска, изоляции генераций, экспорта и OpenAPI;
- 2 UI-теста журнала и кнопки возврата со второго шага;
- Ruff;
- TypeScript typecheck;
- production-сборку Vite.

Результат локального запуска: **PASSED**. Полная историческая регрессия этапов 2–22 этой командой намеренно не запускалась.

## Что остаётся реальным, а не программным

Этап предоставляет место и правила для доказательств, но не создаёт сами доказательства. Чтобы конкретная выкройка получила настоящий допуск, её нужно распечатать на двух физических принтерах, измерить, передать конструктору и изготовить три макета на разных фигурах. Пилот с тётей и такие записи пока не проводились.
